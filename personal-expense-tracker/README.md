# Ledgerly Personal Expense Tracker

A small full-stack finance tracker with separate static frontend and Flask REST API. It stores accounts, income, expenses, and monthly budgets in SQLite. Each user's records are isolated behind a Flask-Login session.

## Requirements

- Python 3.10 or newer
- VS Code with a static file server extension, or Python's built-in HTTP server

## Run locally on Windows

Open two VS Code terminals from the `personal-expense-tracker` folder.

### 1. Start the backend

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
py run.py
```

The API runs at `http://127.0.0.1:5000`. To verify it, visit `http://127.0.0.1:5000/api/health`; it should return `{"status":"ok"}`.

### 2. Serve the frontend

In the second terminal, return to the project folder and start the static server:

```powershell
cd ..\frontend
py -m http.server 5500 --bind 127.0.0.1
```

Open `http://127.0.0.1:5500`. The frontend uses credentialed `fetch()` requests to the backend; open it at this address rather than as a `file://` page. Flask CORS is configured for this exact local origin.

Create an account on the signup page. The app creates `backend/instance/expenses.db` automatically when the backend starts.

### Google sign-in (optional)

Create a Google OAuth web client in Google Cloud Console and add this exact authorized redirect URI:

```text
http://127.0.0.1:5000/api/auth/google/callback
```

Add the client credentials to `backend/.env` (never commit this file):

```text
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret
```

Restart the backend after setting the values. The Google button creates a Ledgerly account on first sign-in or signs into an existing account with the same verified Google email. Apple and Facebook sign-in are not configured.

## Features

- Sign up, sign in, and sign out with password hashes and cookie-based sessions
- Optional Google OAuth sign-in
- Add expenses with a category, date, payment method, and optional description; view, edit, delete, and filter personal expense history
- Record income and see monthly income, expense, and net balance totals
- Set overall or category-specific monthly budgets and track spending progress
- Review current-month category spending and compare it with the matching date range in the previous month
- View a monthly spending-by-category chart and recent expenses
- Responsive layout for desktop and mobile screens

## API overview

All endpoints are prefixed with `/api`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `POST` | `/auth/signup` | Create an account and sign in |
| `POST` | `/auth/login` | Sign in |
| `POST` | `/auth/logout` | Sign out |
| `GET` | `/auth/me` | Read the current session |
| `GET`, `POST` | `/expenses` | List or create expenses |
| `PUT`, `DELETE` | `/expenses/<id>` | Update or delete an expense |
| `GET`, `POST` | `/income` | List or record income |
| `PUT`, `DELETE` | `/income/<id>` | Update or delete an income record |
| `GET` | `/budgets?month=YYYY-MM` | Read monthly budgets and spending |
| `POST` | `/budgets` | Create or update a monthly budget |
| `DELETE` | `/budgets/<id>` | Delete a budget |
| `GET` | `/dashboard` | Read monthly totals and category breakdown |
| `GET` | `/insights` | Read current-month spending and previous-period category comparisons |

Expense list filters are optional query parameters: `category`, `start=YYYY-MM-DD`, and `end=YYYY-MM-DD`.

## Deployment configuration

The backend can be run behind a production WSGI server such as Waitress. Deploy the backend and static frontend separately, and configure the following values in the backend host's environment settings (do not commit credentials):

- `APP_ENV=production`
- `SECRET_KEY`: a long, random secret generated by the hosting provider
- `DATABASE_URL`: a persistent PostgreSQL URL. Production startup fails if this value is missing. PostgreSQL URLs beginning with `postgres://` or `postgresql://` are normalized to the installed psycopg driver.
- `FRONTEND_ORIGIN`: the exact HTTPS origin serving the frontend, without a trailing slash (for example, `https://ledgerly.example.com`)
- `SESSION_COOKIE_SECURE=true`
- `SESSION_COOKIE_SAMESITE=None` when the frontend and backend are on different sites; use HTTPS for both

In `frontend/js/config.js`, set `window.LEDGERLY_API_BASE_URL` to the deployed backend API base, for example `https://ledgerly-api.example.com/api`. This is the one frontend setting used by all pages. The local default remains `http://127.0.0.1:5000/api`.

For a Render web service, set its root directory to `backend`, install with `pip install -r requirements.txt`, and use this start command:

```sh
waitress-serve --listen=0.0.0.0:$PORT run:app
```

Configure a persistent managed SQL database and copy its connection URL into `DATABASE_URL`. Deploy `frontend/` as a separate static site, set its origin in `FRONTEND_ORIGIN`, and update `frontend/js/config.js` to point to the API service. Set `APP_ENV=production` and the secure cookie settings above before exposing the app. The app has not been deployed or tested on Render/Railway as part of this change.
